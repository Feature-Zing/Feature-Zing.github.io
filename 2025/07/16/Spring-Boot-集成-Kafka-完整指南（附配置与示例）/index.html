Spring Boot 集成 Kafka 完整指南（附配置与示例）

kafka整合spring boot实现相关功能

在开发中需要将kafka和spring boot进行整合，来实现消息队列的功能，实现系统解耦，削峰填谷等能力。

POM依赖

<!--kafka 依赖-->
<dependency>
    <groupId>org.springframework.kafka</groupId>
    <artifactId>spring-kafka</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

以上是实现spring boot整合kafka所需要的依赖，在启动类还需要加上**@EnableKafka**注解即可在项目中使用kafka相应功能。

producer application配置

server:
  port: 8095
spring:
  kafka:
    # kafka 地址配置,集群需要使用逗号隔开
    bootstrap-servers: 192.168.0.105:9092,192.168.0.105:9094,192.168.0.105:9096
    #生产者配置
    producer:
      #procedure要求leader在考虑完成请求之前收到的确认数，用于控制发送记录在服务端的持久化，其值可以为如下：
      #acks = 0 如果设置为零，则生产者将不会等待来自服务器的任何确认，该记录将立即添加到套接字缓冲区并视为已发送。在这种情况下，
      #无法保证服务器已收到记录，并且重试配置将不会生效（因为客户端通常不会知道任何故障），为每条记录返回的偏移量始终设置为-1。
      #acks = 1 这意味着leader会将记录写入其本地日志，但无需等待所有副本服务器的完全确认即可做出回应，在这种情况下，
      # 如果leader在确认记录后立即失败，但在将数据复制到所有的副本服务器之前，则记录将会丢失。
      #acks = all 这意味着leader将等待完整的同步副本集以确认记录，这保证了只要至少一个同步副本服务器仍然存活，
      # 记录就不会丢失，这是最强有力的保证，这相当于acks = -1的设置。
      #可以设置的值为：all, -1, 0, 1
      acks: 0
      # 生产者发送消息失败时，发送消息重试的次数，只有在kafka发送时出现异常才会重试
      retries: 3
      #每当多个记录被发送到同一分区时，生产者将尝试将记录一起批量处理为更少的请求，
      #这有助于提升客户端和服务器上的性能，此配置控制默认批量大小（以字节为单位），默认值为16384
      batch-size: 16348
      # 生产者可用于缓冲等待发送到服务器的记录的内存总字节数
      buffer-memory: 33554432
      #ID在发出请求时传递给服务器，用于服务器端日志记录
      client-id: 6c1c6b52-bab3-414f-943c-2e6bf578cb98
      # kafka生产者key的序列化方式和value的序列化方式
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer

consumer application配置

spring:
  kafka:
    bootstrap-servers: 192.168.0.105:9092,192.168.0.105:9094,192.168.0.105:9095
    consumer:
      group-id: future-consumer
      # 消费者是否能够自动提交偏移量
      enable-auto-commit: true
      # 消费者自动提交的频率
      auto-commit-interval: 5000
      # 消费offset取值earliest,latest,none（默认：latest）
      auto-offset-reset: latest
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      max-poll-records: 500
      fetch-min-size: 10
      fetch-max-wait: 10000ms
      # Kafka Consumer Listener 监听器配置
      properties:
        fetch:
          wait:
            max:
              ms: 500 # 如果没有消息，消费者最大间隔多少进行消息拉取，避免消费者在没有消息时一直拉取
    listener:
      missing-topics-fatal: false

建议消费者和生产者设置序列化方式一致，否则容易导出序列化出现问题

Kafka使用

通过之前的配置和pom文件已经把springboot与kafka进行整合，下面是如何使用Kafka实现消息的发送和消息的消费。以及如何保证消息不丢失，消息幂等性，事务消息，批量消费，手动提交消息。

Topic创建

kafka发送消息需要指定topic，在使用之前需要创建topic，可以通过配置方式创建

@Configuration
public class KafkaConfig {

    public static final String easyTopicName = "string-future";

    /**
     * 创建主题，但是每次重启都会重新创建主题
     *
     * @return
     */
    @Bean
    public NewTopic topic() {
        return TopicBuilder
                // 主题名称
                .name(easyTopicName)
                // 分区数量
                .partitions(10)
                // 副本数量,如果副本数量超过broker数量，只会生成固定的副本数,副本数量=broker-1                
                .replicas(2)
                // 构建主题
                .build();
    }
}

通过以上配置在启动项目后会创建一个topic名称为：string-future，partition为：10，并且每个partition副本数量为：2

简单消息发送

发送消息
@Component
@Slf4j
public class StringMessageProducer {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    
     /**
     * 简单消息发送
     * @param message
     */
    public void syncSendMessage(String message) {
        kafkaTemplate.send(KafkaConfig.easyTopicName, message);
    }


    /**
     * 发送消息后,会自动回调方法，进行反馈，是否发送成功
     *
     * @param message
     */
    public void syncSendMessageWithRollBack(String message) {
        ListenableFuture<SendResult<String, String>> send = kafkaTemplate.send(KafkaConfig.easyTopicName, message);
        send.addCallback(new SuccessCallback<SendResult<String, String>>() {
            @Override
            public void onSuccess(SendResult<String, String> result) {
                log.info("metaData send success,messsage int topic:{},partition:{},detail:{}", result.getRecordMetadata().topic(),
                        result.getRecordMetadata().partition(), result.getRecordMetadata());
            }
        }, new FailureCallback() {
            @Override
            public void onFailure(Throwable ex) {
                log.info("send failed", ex.getMessage());
            }
        });
    }

}

KafkaTemplate提供了send 方法进行消息的发送，可以设置回调函数，建议设置回调函数，查看消息发送是否成功或者失败原因、打印相关日志以及对消息异常后，进行相应处理，进行重试或者是记录数据库等。

KafkaTemplate 通过泛型可以发送不同类型的数据，根据指定类型发送，如果需要发送对象需要设置Value值为Object或者是具体的对象类型，实现注入

KafkaTemplate 默认注入，也可以自己配置

顺序消息

kafka的顺序只能保证分区消息的顺序，不能保证topic是顺序的，要保证消息的顺序性，需要消息发送方发送的时候保证消息按照规定顺序进行发送，并且不能发送重复消息，而消费方需要保证消费时，不重复消费，并且消费方需要使用单线程进行消费。

以下通过key来将消息发送到同一个partition。

@Component
@Slf4j
public class StringMessageProducer {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;

    
     /**
     * 简单消息发送
     * @param message
     */
    public void syncSendMessage(String message) {
        kafkaTemplate.send(KafkaConfig.easyTopicName,"key", message);
    }

}
事务消息

发送事务消息时，需要在生产者和消费者进行配置保证事务消息的正常发送，以及消费方正常消费，但是kafka事务消息只是指在批量发送消息时，一组消息要不都是成功要不都是失败，同时还需要消费者正确设置隔离级别，否则会消费到为最终提交的事务消息。

生产方发送事务消息时需要开启配置

spring:
  kafka:
    producer:
      # 开启事务
      transaction-id-prefix: "producer-tran"

消费方需要设置隔离级别为：read_commited，默认为read_uncommited，如果未设置正确隔离级别，会消费到还未提交的事务消息

spring:
  kafka:
    consumer:
      # 开启事务消息时，需要设置隔离级别的commited，防止消息读取失误
      isolation-level: read_committed

生产方发送消息代码如下：

@Component
@Slf4j
public class TranProducer {

    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;


    public void syncSendMessage(String message) {
        boolean transactional = kafkaTemplate.isTransactional();
        log.info("kafka start tran:{}", transactional);
        try {
            kafkaTemplate.executeInTransaction(kafkaTemplate -> {
                kafkaTemplate.send(KafkaConfig.easyTopicName, message + 1);
                try {
                    TimeUnit.SECONDS.sleep(10);
                } catch (InterruptedException e) {
                    throw new RuntimeException(e);
                }
                kafkaTemplate.send(KafkaConfig.easyTopicName, message + 2);

                throw new RuntimeException("发生异常");
            });
        } catch (Exception e) {
            log.info("出现事务异常");
        }
    }

除了全局配置开启事务之外，还可以在方法中设置进行发送消息

消息消费

普通消费

消息发送成功后通过**@KafkaListener** 注解在方法上进行注释，设置相关参数就可以消费指定topic的topic或者是指定的partition

@Component
@Slf4j
public class StringMessageConsumer {

    @KafkaListener(topics = "string-future", groupId = "future-consumer")
    public void consume(ConsumerRecord<String, String> consumerRecord) {
        int partition = consumerRecord.partition();
        String topic = consumerRecord.topic();
        log.info("A: topic:{},partition:{},message:{},detail:{}", topic, partition, consumerRecord.value(), consumerRecord.toString());
    }

    @KafkaListener(topics = "string-future", groupId = "future-consumer")
    public void consume2(ConsumerRecord<String, String> consumerRecord) {
        int partition = consumerRecord.partition();
        String topic = consumerRecord.topic();
        log.info("B: topic:{},partition:{},message:{},detail:{}", topic, partition, consumerRecord.value(), consumerRecord.toString());
    }

    @KafkaListener(topics = "string-future", groupId = "future-consumer")
    public void consume2(String data) {
        log.info("C: data:{}", data);
    }
}

以下是简单的使用举例，实现对topic的监听：

  1. 基本使用

    @KafkaListener(topics = "topicName")

  2. 指定消费者组

    @KafkaListener(topics = "topicName", groupId = "groupName")

  3. 监听多个主题

    @KafkaListener(topics = {"topic1", "topic2"})

  4. 使用topic pattern匹配主题

    @KafkaListener(topicPattern = "topic.*")

  5. 动态指定主题

    @KafkaListener(topics = "#{@environment.getProperty('kafka.topic')}")

  6. 指定监听主题的分区，加入消费者组后，不受动态消费者组动态分区

    @KafkaListener(topicPartitions = {
    @TopicPartition(topic = "topicName", partitions = {"0", "1"}),
    @TopicPartition(topic = "anotherTopic", partitions = "0")
})
手动提交消息

在某些场景下为了保证消息能够正确消费，不丢失，我们需要手动提交消息offset，kafka自动提交offset但是默认定期5s提交一次，如果出现异常会导致offset提交失败，导致消息出现重复消费。手动提交offset有以下优点：

  1. 保证消息处理语义一致性
  2. 避免消息丢失或者重复消费
  3. 更细粒度的控制

要实现手动提交消息的offset，需要将消费者设置为手动提交模式。

spring:
  kafka:
    listener:
      # 开始手动确认消费消息
      ack-mode: manual_immediate

实现代码如下：

@Component
@Slf4j
public class StringMessageConsumer {

    @KafkaListener(topics = "string-future", groupId = "future-consumer-manual")
    public void consume(ConsumerRecord<String, String> consumerRecord, Acknowledgment ack) {
        int partition = consumerRecord.partition();
        String topic = consumerRecord.topic();
        log.info("A: topic:{},partition:{},message:{},offset:{},detail:{}",
                topic, partition, consumerRecord.value(), consumerRecord.offset(), consumerRecord.toString());
        // 手动提交偏移量，如果不提交，重新启动应用后会再次对消息进行消费
        ack.acknowledge();
    }
}
批量消费

在kafka消费者中，默认使用的是单个消费的方式，如果消息产生速度过快，单个消息消费的方式会很慢，并导致消息积压，但是kafka提供了一种批量消费的方式，通过一次性拉取一组消息给消费监听器，然后进行消费，加快消息的消费。

但是需要进行配置

spring:
  kafka:
    consumer:
      # 批量拉去最大条数
      max-poll-records: 5
      fetch-min-size: 10
      fetch-max-wait: 10000ms
      # Kafka Consumer Listener 监听器配置
    listener:
      # 监听器进行批量监听
      type: batch

代码如下：

@Component
@Slf4j
public class StringMessageConsumer {

    @KafkaListener(topics = "string-future", groupId = "future-consumer-batch")
    public void consume(List<ConsumerRecord<String, String>> consumerRecords) {
        log.info("A batch consumer: size :{}", consumerRecords.size());
        for (ConsumerRecord<String, String> consumerRecord : consumerRecords) {
            int partition = consumerRecord.partition();
            String topic = consumerRecord.topic();
            log.info("A: topic:{},partition:{},message:{},detail:{}", topic, partition, consumerRecord.value(), consumerRecord.toString());
        }
    }
}
